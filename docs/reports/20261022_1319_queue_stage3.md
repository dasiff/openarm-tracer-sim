# Overnight queue, Stage 3: the follower and its integration (behind `NAV_CFG["follow"]`, default False)

Written for: David (decisions on the follower's starting values and the lean caveat).

## What was built
- `src/nav_follower.py`: Regulated Pure Pursuit with Nav2's parameter names (lookahead, curvature, cost, approach scaling), the curvature feed-forward (`k_fb`), acceleration limits, rotate-in-place when the heading is more than 0.35 rad off the path, stop and replan when the base leaves the route by more than 5 cm (up to 3 replans, then a failure with the reason `replans used up`), no route is a failure at once (`no path`, no retries). The last centimetres are today's go-to-pose controller (aim 1 cm / 0.5 degrees, at rest 0.3 s, corrective re-approaches), started when the path's end is reached. Row M149; settings in `NAV_CFG`.
- Staging hook (`src/staging_source.py`): with `NAV_CFG["follow"]` the DRIVE builds the grid from the model (footprint at the zombie pose, the model's 70 static geoms as obstacles), plans, follows; the report gains a `nav` key (routes, replans, cross-track, planning time, a 0.5 s trace). With it off the code path is today's.
- Replans from inside the lead-in (a push near the end) use a direct route to the goal, verified like the others (found by the test: the lead-in start was behind the robot and the replan tried to U-turn).
- The smoother's pull to the A* points falls in open space (`w_data_open_frac` 0.002, stop tolerance 2e-5 m, 1500 iterations; M148): the 5 cm grid's jog before the lead-in had made curvature 6.5 1/m and the real base drifted 5 cm; now 0.13 1/m.

## N9 lean measurement (`experiments/nav_lean_sweep.py`, `data/nav_lean_sweep.json`)
Arms at the zombie pose, drive pedestal height, no beaker: 6 straight runs (0.3 and 0.5 m/s, 0.1, 0.2, 0.4 m/s^2), 6 in-place turns (0.4 and 0.8 rad/s, 0.2, 0.4, 0.8 rad/s^2), 2 arcs. Peak tilt of `base_link`: 0.002 to 0.015 degrees in every run (the limit is 1 degree, the margin 0.8). Caveat: the sim's base is velocity driven and the drive zeroes roll and pitch (src/base_control.py), so the sim cannot show real tipping; the numbers say nothing about the hardware. The carried-beaker sweep was not run (queue: placeholders). So NAV_CFG keeps today's gentle values as conservative placeholders (0.3 m/s, 0.1 / 0.15 m/s^2, 0.4 rad/s, 0.2 rad/s^2); nothing was changed.
