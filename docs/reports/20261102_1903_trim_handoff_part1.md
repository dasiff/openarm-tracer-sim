# Trim handoff blend, part 1: no freeze at the grasp; a ramp-in blends the trim to its reference (no simulation)

Written for: David (design review). Branch held-weight-ramp-sag-off. Build commit 3d44e7d. Decisions M230, M231, M232 (DECIDED, built, not run); M229 RESOLVED by M230. Design plan section 15 items dd, ee, ff. Acronyms: C = the sag correction (the integral trim); ref = the correction saved at the grasp; full = the correction on the first tick of a ramp-in; kg = kilograms; ms/s = seconds.

**Plain summary.** The freeze no longer starts at the grasp. During the lift the sag correction learns the beaker's sag as normal. When the mass ramps in at the weighing, the correction is moved back to its grasp value in step with the mass, so the sag learned during the lift passes over to the feedforward's mass term. The unit tests pass; nothing has been run in a simulation, so the lift is not yet shown to work.

## Limits and choices (please check)
1. The blend only runs on move ticks: the trim helper is called from the move branch of the step. The weighing (CHECK) step has no move, so the blend starts on the first move tick after the weighing (the place's OVER). In the first tick of that move, the correction is therefore latched as full before any blend (INFERRED from the code; the trim does not change during CHECK).
2. A ramp-in that is retargeted to a lower mass becomes a ramp-out for the helper: the blend is abandoned and the correction freezes at its value. It returns to ref only when a ramp-in finishes. Not reached in the normal flow.
3. The ref is kept until the next grasp or a reset, as the brief says, so a second ramp-in in the same pick would blend to the same ref.
4. The `sag_reset_at_skill_start` key (M227) still gates the skill-start reset, and it now also clears the handoff record.
