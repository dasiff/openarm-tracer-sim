## What changed

- Reset rule: the open-catch release (hold_steps callback) calls SagLayer.release_open, the only arming call. The reset comes when that release completes (fingers at rest, close_min_s after). The per-command arming in sag_correct is removed.
- Logging (signal trace, per hand, after the verdicts): sag label, planned pad pose, forward-kinematics pose of the solver's joint targets, their difference (position and orientation), correction C (position and rotation), reset cause, guard counter. A trace row is written at the start of a tick (the hook runs before the sources), so the row shows the state the previous tick left.

## NOT BUILT, needs decision

1. **Trim during the navigation arm hold.** The layer trims every arm command, including the arms held at home during navigation (tick 38 onward). With the release-only rule nothing clears it before the pick, so it reaches the 40 mm limit. Default as built: it runs. This is the most likely cause of the scripted and mock IN failures in this run, now that the periodic reset no longer hides it.
2. **Reference offset in IN.** Forward kinematics of the solver's targets minus the planned point averages +2.15 mm in z during IN. David kept the reference, so it is unchanged. The offset integrates into the trim, which wound up to the limit.
3. **Correction limit.** The 40 mm limit (sag_max_m) is hit in every run from the navigation onward; the gain and limit are unchanged (David's decision 4). Default: as built.
4. **Skill-start and recovery-start resets.** The loop cannot see them (old lines 265 to 267 and 292). Default: carry-over, as today.
5. **Non-held open completion.** The old code reset at any scripted OPEN completion; the new rule resets only on a caught release. Default: release only.
6. **Known limit.** The trim runs on joint-only moves (recovery HOME), as David decided.
7. **Navigation-phase correction not visible in commands.** The trace shows a correction from tick 38, but the episode log's arm commands match the baseline until 66.10 s. I did not find where that correction goes. Needs a check of what the bridge sends during NAV.
8. **Release reset not exercised in a run.** No grasp happened in either run, so the release reset is verified only by the synthetic test.
