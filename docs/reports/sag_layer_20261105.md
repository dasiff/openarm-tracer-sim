## Part 2: the build
- `src/sag_layer.py` (new): `_clip_norm` and `_sag_trim_step` moved unchanged from src/mpvi_modules.py; `SagLayer` (one per arm): `correct(q_src, data, t, nominal_dt)`, `start_open(t)`, `track_open(data, t)`; module dict `SAG_TRACE` (logging only: the run recorder's C_p and C_r columns).
- Reference: `_pose` takes the source's 7 joint targets, sets them on a scratch copy of the robot state (the other joints from the state), runs `mj_kinematics`, and reads the pad pose with `MinkArm.pad_pose`. Measured: `arm.pad_pose(data)`. Correction: `_sag_trim_step(C, PICK_PLACE_CFG, ..., p_ref - p_now, rotvec(R_ref R_now^T), dt)`. Output: `MinkArm.step(data, p_ref + C_p, rot(C_r) R_ref)` with the layer's own warm start, `dt` = the command's period (`min(time since the last correction, nominal)`).
- `src/control_loop.py`: `sag_correct(cmd)` runs for every command before `bridge_take`; `track_open` runs each tick; the open watch starts at a passing open command and at the catch's release; `sag_home_q` (posture target; the pipeline sets the task's home poses; without it, the start joints).
- `src/mpvi_modules.py`: the trim call, the correction dictionary, the restart subtraction, the skill-start reset, the recovery reset, the gripper-open reset and the trace fields `C_p`, `C_r` are removed; `_clip_norm` and `_sag_trim_step` are removed (moved). The scripted solver is called for the planned pose: `arm.step(data, p_ref, R_ref)`.
- `src/task_config.py`: `sag_reset_at_skill_start` removed (it had no effect with the switch off); `SAG_LAYER_CFG = {"enabled": True}` added.
- `src/mpvi_pipeline.py`: `loop_cfg` carries `sag_home_q` for every source.
- Experiments that imported the moved helpers now import from `src/sag_layer.py`: `experiments/held_mass_ramp_test.py`, `experiments/place_over_turn_measure.py`. `experiments/bounce_freeze_run.py` sets the removed config key in its own process only; setting it now has no effect (not edited).

Deletions: from src/mpvi_modules.py: `_clip_norm`, `_sag_trim_step`, `C = {...}`, the restart subtraction (2 lines), the skill-start reset (3 lines), the recovery reset (2 lines), the trim call, the solver's trim term, the open reset (3 lines), and the trace keys `C_p`, `C_r`. From src/task_config.py: `sag_reset_at_skill_start`.

- Exit status 1. Pick OVER, DOWN, IN run; IN fails twice: "not reached after 15.1 s: 3.3 mm and 1.1 deg from the waypoint" (attempt 1 at t=71.2 s, attempt 2 at t=100.1 s). The retry is used up, so the plan fails at segment 2/4.

- Trim at the end of each move step, from the C_p columns (mm, x y z):

  - pick DOWN (tick 9916 start): about -6.5 -3.1 -0.7.
  - pick IN (tick 10470 start): about -2.3 -0.3 +1.5.

The old per-skill-start reset (sag_reset_at_skill_start) was removed in M262, so the correction carries from the first attempt's pick into the second attempt's OVER step. This is a behaviour change from the baseline and is part of why the second attempt starts from +4.7 mm.
